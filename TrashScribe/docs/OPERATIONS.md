# Operations: environment, data, queue, monitoring, paper build

## Environment

* Conda env **`trashscribe`** (exact pins in [environment.yml](../environment.yml): Python 3.12.3, torch 2.9.1+cu130,
  transformers 5.2.0). Use `~/anaconda3/envs/trashscribe/bin/python` in units and scripts.
* Hugging Face models are read from the local cache with `HF_HUB_OFFLINE=1`. Needed:
  `facebook/sam2.1-hiera-tiny` (149 MB, the backbone), `openai/clip-vit-base-patch16` (text encoder, E8 teacher,
  raw-CLIP baselines), and for baselines `facebook/sam3` (3.3 GB, gated licence), `google/owlv2-base-patch16`,
  `IDEA-Research/grounding-dino-tiny`, `nvidia/mit-b2`.
* Text embeddings of the schema are cached in `runs/_cache/text_clip_b16.pt` (git-ignored, rebuilt on demand).
* Tests: `python -m pytest tests -q` (14 pass).

## Data (not in git)

`data_root: ~/data/waste` (see `configs/base.yaml`, registry `configs/datasets.yaml`):
`TACO/` 620 MB, `zerowaste-f/` 706 MB, `UAVVaste/` 261 MB, `MJU-Waste/` 2.3 GB, `BePLi_v2/` 769 MB,

## Host memory

The workstation has 15 GB RAM and `systemd-oomd` kills the **whole user session** (VS Code included) when
memory pressure stays above 50 % for 20 s. VS Code alone holds several GB and most of the swap. Rules:

* never run training or heavy analysis in the VS Code terminal;
* run every heavy job as its own capped unit, e.g.
  `systemd-run --user --unit=<name> --collect -p MemoryMax=3G -p MemorySwapMax=0 -p Nice=10 --working-directory=$PWD --setenv=HF_HUB_OFFLINE=1 <python> <script>`;
* CPU jobs next to the queue: `--setenv=CUDA_VISIBLE_DEVICES=` and a `CPUQuota`;
* check `cat /sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/memory.pressure` while a big job runs;
* SAM 3 on CPU needs fp32 (no AVX-512 bf16 on this CPU) and about 4.6 GB.

## GPU queue

* Service **`trashscribe-queue`** runs `scripts/run_queue.py`, which reads [configs/gpu_queue.yaml](../configs/gpu_queue.yaml)
  **before every job** (edit it while the queue runs to reorder or add jobs). A job is done when
  `runs/<name>/test_metrics.json` exists; training jobs are resumed with `--resume` from `last.pt`; kinds:
  `train` (`train.py`), `segformer` (`baseline_segformer.py`), `zeroshot` (`baseline_zeroshot.py <config> <args>`).
  `max_attempts` per job (default 3); two CUDA OOMs in a row stop retrying a job.
* Status: `runs/_queue_status.json` (history + current), log `runs/_queue.log`, per-run logs `runs/<name>.log`.
* Timer **`trashscribe-report`** runs `scripts/report_results.py` every 15 min (AUTO block of RESULTS.md).
* Stop / restart commands: [stop_and_restart.txt](../stop_and_restart.txt). **After a reboot both units are gone**:
  re-run the "RESTART RUNS" and "RESTART REPORT TIMER" commands; the running job resumes from its last epoch.
* Order rule (owner): most significant expected result first.
* GPU jobs outside the queue must cap memory (`posthoc.py ... --mem-frac 0.17`) or run on CPU; the training
  run uses about 6 GB of 8 GB.

## Monitoring

`conda activate trashscribe && python scripts/progress.py --watch 30` (restart it after code changes). It shows
the running job, finished jobs with their headline metrics ("n/a" = metric undefined, e.g. single-class test
sets), the queue with ETAs and the grid end date. SegFormer runs take about 11 h, more than the estimate.

## Post-hoc analyses (`scripts/posthoc.py`)

`dump RUN --split test|val [--clip] [--mem-frac 0.17]` (per-object embeddings; E8 also stores `zclip`),
`naming`, `clipret [--visual clip|zclip]`, `leakage RUNS...`, `values RUNS... --values "field: value" ...`,
`tiles RUN [--device cpu]`. Outputs in `runs/<run>/posthoc/` and `runs/_posthoc_*.json`.

## Paper

`paper/main.tex` (Springer Nature `sn-jnl`, `sn-basic` style), `references.bib`, `title_page.tex`,
`cover_letter.tex`. Build: `cd paper && pdflatex main && bibtex main && pdflatex main && pdflatex main`.
Tables in `paper/tables/*.tex` are generated by `python scripts/make_tables.py` (also run by the queue after
every job); figures by `scripts/make_figures.py` (qualitative), `scripts/make_comparison.py` (literature
comparison; `run <method>` per method in capped CPU processes, then `draw`), `paper/figures/pipeline.tex` (TikZ).
Note for `sn-jnl`: `\footnotesize` is smaller than `\scriptsize`. Red `\tbd{}` marks pending numbers or text.
